# Releases / Sürümler

## English

Hamartia publishes one GitHub Release after each merged PR once the desktop release workflow is active. Release tags use a sequential themed code (`ARETE-001`, `ARETE-002`, ...). Each release includes bilingual notes and the Windows installer, Debian package, and AppImage.

The workflow appends each published bilingual note to this file. Pull requests merged before the workflow is introduced cannot trigger a release retroactively.

See the [GitHub Releases page](https://github.com/Nec0ti/hamartia/releases) for current downloads and notes.

## Türkçe

Masaüstü sürüm iş akışı etkinleştikten sonra birleştirilen her PR için bir GitHub Release yayımlanır. Sürüm etiketleri sıralı ve temalı kod kullanır (`ARETE-001`, `ARETE-002`, ...). Her sürümde iki dilde notlar, Windows kurulum programı, Debian paketi ve AppImage bulunur.

İş akışı yayımladığı her iki dilli notu bu dosyaya ekler. İş akışı eklenmeden önce birleştirilmiş PR'lar geriye dönük olarak release tetikleyemez.

Güncel indirme dosyaları ve notlar için [GitHub Releases sayfasına](https://github.com/Nec0ti/hamartia/releases) bak.

`ARETE-061` — [PR #65](https://github.com/Nec0ti/hamartia/pull/65): fix\: keep desktop readiness details private

### Highlights

The local readiness endpoint no longer returns the user's absolute data folder path or raw filesystem error text\.

### Behavior and why

The unauthenticated \`\/healthcheck\/ready\` response still reports whether storage is ready\. Its success response now contains only the status\. Storage failure returns HTTP 503 with a generic message, preventing callers that gate startup on HTTP success from proceeding when storage is unavailable\.

### How to use

No action is needed\. Existing launchers continue to check the HTTP readiness status\.

### Compatibility / migration

No data or migration changes are needed\. The \`data\_dir\` success field and detailed \`error\` text are removed from this endpoint; repository callers only use the status code\.

### Verification

The focused readiness tests passed 2\/2, covering unauthenticated success and HTTP 503 with generic failure details\. \`git diff \-\-check\` passed\.

### Not run / known limitations

The full backend suite, packaged\-app smoke, and dynamic security testing were not run\. The review was source\-based and scoped to local desktop\/backend boundaries\.
