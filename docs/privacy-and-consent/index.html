Privacy and consent

Where records are stored and what optional AI requests send.

By default, study records are stored in the current OS user's application-data folder. There is no automatic cloud sync. Moving or sharing a backup is a separate action.

Local records

Exam results, saved missed questions and images, review attempts, topic-practice records, Clock timers and reminders, progression data, and settings are stored locally. The Clock notification preference and reminders are local state; due alerts are checked only while Hamartia is running and the device is awake. Notifications can be suppressed by OS settings.

Student profile

The optional student profile contains only the values you choose to enter: nickname, age in whole years, grade/year, curriculum label, study preferences/goals, and a built-in avatar. Eight avatar designs are available immediately; three optional cosmetic designs unlock at existing XP levels 2, 3, and 5 (500, 1,000, and 2,000 XP). Unlocks never deduct XP or depend on streaks. The profile is stored in the local app data folder and included in manual ZIP backups. It has no birth date or gender field. Curriculum labels are user-entered and Hamartia does not assert or verify official alignment. The profile and local-study XP stay out of Study Agent and question-analysis requests. A future personalized Study Agent feature would require a separate explicit request and privacy disclosure. You can edit or delete the profile in Settings.

Study Agent requests

Each request requires explicit consent and goes directly to the selected provider. ChatGPT calls use OpenAI's public Responses API with storage disabled by the app. The prompt and bounded summary categories are shown before sending. In Practice Session entry, the current conversation is sent without saved study records or the general summary. ChatGPT receives a strict quote-only evidence function; the configured endpoint receives the equivalent evidence-only tool. Hamartia checks quote hints against the host-owned transcript, shows a verified preview, and writes only after explicit approval. The provider cannot write records. Hamartia does not store Study Agent transcripts. Configured endpoints may be remote and may have their own retention rules.

Prepare learning evidence is another conversation-only mode: the provider returns field-and-quote hints, and the host checks every exact quote against the expected student turn before showing a preview. A separate explicit approval writes only self-reported fields. Qualified activity wording is kept as written, with no inferred date, mastery, or whole-task completion. A URL is stored only when explicitly present and is never fetched. Invalid/ambiguous evidence or cancellation writes nothing.

Text-only missed-question capture sends only its current student conversation after consent. The host verifies exact problem/label quotes and displays a canonical preview; separate approval creates the Question record. Subject/topic may be skipped, including with the same skip answer in both turns. Saved study data, images, previous chats, URLs, analysis, tags, and curriculum mappings are excluded. Invalid or cancelled drafts write nothing.

Single-subject branch-exam capture

This is a separate consent-gated conversation flow. After explicit consent, the selected provider (ChatGPT or a configured endpoint that may be remote) may receive the current student transcript (including quoted exam facts) and expected field, and returns only exact field/quote hints. The scoring-profile ID/version, scoring rules, and record IDs remain host-side; the host validates the quoted date, subject, result counts, and duration, then computes net/XP from the host-selected immutable profile. The user reviews the canonical preview and separately approves creation. This does not create sectioned TYT/AYT exams; existing manual entry is unchanged.

Sectioned TYT/AYT exam capture

This separate consent-gated conversation records one sectioned exam with 1–6 user-specified sections. The host asks for TYT or AYT, exact date, duration, section count, and each section's subject and correct/incorrect/blank counts. No defaults or official subject roster are assumed. After consent, the selected provider (ChatGPT or a configured endpoint that may be remote) receives only the student transcript and expected field for exact quote hints. The scoring profile is selected on this device before provider dispatch; profile ID, rules, and snapshot stay host-side and are not conversational facts. The host validates quotes against the expected student turn, controls section order, aggregates totals, and computes net/XP from the selected immutable profile. The user reviews the full preview and separately approves creation. Cancellation, invalid or ambiguous answers, and stale or unapproved drafts write nothing. The transcript and signed continuation state are not persisted.

Question analysis

Question analysis is a separate user-triggered request. Before every send, a local-only preview displays the sanitized hostname and effective port, local/remote class, HTTP/HTTPS scheme, model, saved question/OCR text and filename fields, whether image bytes are included, and the authentication-value category without showing its value. Question/OCR text is limited to 64 KiB of UTF-8 data and saved images to 10 MiB. The endpoint may be remote. Only explicit approval sends one request; cancel sends no provider request. Failed calls are not automatically retried. A blank key setting currently sends the SDK placeholder value. Do not approve an operator or transport you do not trust.

Credentials

ChatGPT renewable credentials use OS-protected storage; sign-in is unavailable if that protection cannot be used. The configured endpoint API key is stored unencrypted in local settings, not returned by the Settings API and not included in backups. Do not publish logs, screenshots, or backups containing private study material or credentials. See Study Agent and providers and Backup and restore.
