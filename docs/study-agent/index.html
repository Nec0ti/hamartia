Study Agent and providers

Select the desktop Study Agent provider and understand its controls.

The Study Agent is optional and available in the packaged desktop app. Question analysis is a separate optional action in My Mistakes. Neither is needed for ordinary exam, review, practice, or Clock flows.

ChatGPT subscription

The desktop Study Agent defaults to ChatGPT subscription. Select sign-in, complete the ChatGPT flow, and separately approve OpenAI's request to use the ChatGPT plan. Available models and usage limits depend on the account. Hamartia does not silently switch providers if a request fails. Sign out attempts remote revocation; follow the app's instructions if OpenAI cannot confirm it.

OpenAI-compatible server (local or remote)

In Settings, enter the endpoint URL, model name, and optional API key. Select Local or remote OpenAI-compatible server explicitly in Study Agent. This option may point to a server on this computer or a remote host. Hamartia does not verify that it is a local model or isolated from the network. Review the exact URL, transport warnings, and per-request consent; a remote operator may retain requests under its policy. The API key is stored unencrypted in local app settings and is omitted from backups and API responses.

Ollama and LM Studio setup examples

Run the server on the computer running Hamartia, then set the URL and model name in Settings. These default ports and model IDs are examples; use the port and exact model identifier reported by your own server.

Ollama

  1. Install and start Ollama, then download a model such as qwen3:8b with ollama pull qwen3:8b.
  2. In Hamartia Settings, use URL http://localhost:11434/v1/ and model name qwen3:8b. Ollama documents port 11434 for its local OpenAI-compatible API. A blank Hamartia API key is fine for Ollama; its compatibility docs say the client key is ignored.

Ollama OpenAI compatibility docs · Ollama Qwen3 model list

LM Studio

  1. Download a model and start the server from Developer, or run lms server start. These compatibility examples assume port 1234; check the server's configured or last-used port.
  2. For port 1234, set URL to http://localhost:1234/v1. Get the model name from the id field returned by curl http://localhost:1234/v1/models. Leave the API key blank unless you enable server authentication.

Use the actual configured/last-used port in both the URL and model-list command. LM Studio OpenAI-compatible endpoints · LM Studio model IDs · LM Studio server start and bind options

Remote endpoint: If the model server is on another computer, configure its reachable address instead of localhost. The Study Agent shows a non-loopback host warning and asks for consent before each request. Local-looking model names and OpenAI compatibility do not prove where inference runs or who can access the service.

Consent and request content

Before each Study Agent request, Hamartia displays a consent screen. Study-guidance requests send the typed prompt plus a bounded summary of saved study counts, subject/topic/tag summaries, topic-practice aggregates, and up to eight user-entered curriculum references. The Prepare a practice set mode is different: it sends only student messages from that practice-entry conversation, with no saved study records or summary. Saved question text and images and Study Agent conversation history are not included or stored by Hamartia. The consent screen describes the destination and data categories. Read it before sending and decline if you do not want the request sent.

Prepare learning evidence

This separate mode sends only the current conversation to the selected Study Agent provider after its consent step. The provider can suggest exact source quotes and field names; Hamartia binds each quote to one student message, checks fields in a fixed order, and asks a localized follow-up when evidence is missing or ambiguous. The final preview shows the exact quotes and values. Saving requires a separate explicit approval. The flow records only the student's self-report: it does not infer a date or mastery, and preserves qualified activity wording without upgrading it to whole-task completion. An optional reference URL must appear explicitly in the conversation; Hamartia never fetches it. Invalid, hypothetical, negated, incomplete, or cancelled drafts write nothing. The conversation is not stored by Hamartia.

Capture a missed question from text

Select Capture a missed question in Study Agent and paste the exact problem text as one message. After per-request consent, only the student messages in that conversation go to the selected provider; saved study records, images, old chats, and summaries are excluded. Subject and topic are optional: answer with your own exact words or use the localized skip option, including the same skip answer for both fields if needed. The provider returns only field/quote hints. Hamartia binds each hint to the host's expected, newest complete student turn and shows exact source quotes in a preview. Review that preview; only its separate approval creates a Question record. No image, URL, analysis, tag, or curriculum mapping is added. Invalid, ambiguous, hypothetical, negated, incomplete, or cancelled drafts write nothing. The transcript is not stored.

Conversational practice entry

Select Prepare a practice set, then choose a scoring profile before sending. The choice and complete immutable rule snapshot are host-selected and bound into the preview digest and approval; provider arguments cannot select or change the profile. This flow creates completed PracticeSession records only; it does not edit exams, mistakes, settings, or backups. The selected provider receives only the student messages, without the saved study summary or profile-selection fields. Include explicit labeled values for date (YYYY-MM-DD), subject, topic, correct, incorrect, blank, duration_minutes, and duration_seconds. Hamartia independently extracts those values and quotes their source messages; differing or unsupported provider proposals are rejected. Missing, conflicting, and invalid values produce localized deterministic questions. A correction across conflicting turns must use correction: field: value (or düzeltme: alan: value). No record is written while required fields remain unresolved.

Review every field, source quote, profile name/version, and exact scoring rule in the preview, then approve that exact preview and confirm the save. Hamartia recomputes the preview digest and performs duplicate detection with the create operation under one storage lock. A matching date, subject, and topic requires an explicit choice to add a separate new record or cancel; this flow never updates an existing record. Cancelling or leaving the preview saves nothing. The preview integrity check protects against stale changes, not a malicious process running as the same OS user; other local API routes already allow direct record creation.

Capture a single-subject branch exam

Select Capture a branch exam for one subject; this flow does not create sectioned TYT/AYT exams. After per-request consent, the selected provider (ChatGPT or a configured endpoint that may be remote) may receive the current student transcript (including quoted exam facts) and the host's expected field so it can suggest only exact {field, quote} evidence hints. The scoring-profile ID/version, scoring rules, and record IDs stay on this computer and are never sent to the provider. Hamartia validates dates, subject and nonnegative result/duration values from the quoted student turns, asks a localized follow-up when evidence is missing or ambiguous, and computes net/XP on the host using the host-selected profile. Review the exact values, source quotes, profile snapshot, and net/XP in the canonical preview; a separate explicit approval is required to save. Invalid, hypothetical, negated, incomplete, cancelled, stale, or altered replays do not create another record. Existing manual and sectioned exam entry remains separate.

Capture one sectioned TYT/AYT exam

Select Capture a sectioned TYT/AYT exam to enter one exam with 1–6 explicitly named sections. The host asks for TYT or AYT, the exact date, duration, section count, then each section's subject and correct/incorrect/blank counts in order. There is no default date, duration, section count, or subject roster, and this flow makes no claim that the entered sections match an official roster. After per-request consent, the selected provider (ChatGPT or a configured endpoint that may be remote) may receive only the student transcript and expected field as context for exact quote hints. The scoring profile is selected on this device before provider dispatch; its ID, rules, and snapshot are not sent or treated as conversational facts. Hamartia validates each quote against the expected student turn, controls section order, aggregates section counts, and computes net/XP using the host-selected immutable profile. Review the exact sections, quotes, aggregate totals, profile and score in the preview; a separate explicit approval writes the exam. Cancellation, invalid or ambiguous answers, stale state, and unapproved previews write nothing. The transcript and signed continuation state are not persisted.

Question analysis

“Review with AI” uses the configured OpenAI-compatible endpoint, which may be local or remote. Before every request, a local-only preview shows the sanitized hostname and effective port, endpoint class, HTTP/HTTPS scheme, model, whether saved question/OCR text and image filename fields are sent, whether saved image bytes are included, and the authentication-value category without revealing the value. Approving sends one request; cancel sends none. Failed provider requests are not automatically retried. See Privacy and consent.
