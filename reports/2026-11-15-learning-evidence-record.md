# User-entered learning-evidence records

## Scope

Added a separate `learning_evidence.json` collection for a student's own report of an activity completed from a Study Plan topic suggestion. Each record stores the selected subject/topic, the user's activity description and observation, the user's calendar date, optional HTTP(S) reference text, and stable ID/creation time. The API supports list/create/edit/delete with field trimming, bounded lengths, strict ISO date, and HTTP(S)-only URL validation. Hostnames are syntax-checked with the explicit `idna` dependency in UTS46 non-transitional mode and DNS label/length limits; this does not emulate all browser URL parsing or resolve the host. The visible reference link shows the browser-parsed host (for example, `https://0x7f000001` is shown as `127.0.0.1`). References are not fetched. Existing backup ZIPs without this optional collection restore it as empty; current backups include it.

The Study Plan form is available in English and Turkish. It requires selecting a suggested topic and entering the activity and observation; users can date, optionally link, edit, and delete records. The UI describes completion as self-reported. These records do not touch review attempts, practice/exam results, or XP, and no model/provider call or inference path was added. EN/TR wiki and backup pages explain these limits.

## Limits

The learning-evidence entry is the student's self-report; Hamartia does not verify activity completion, fetch links, check their availability or content, grade reflections, or infer learning/mastery. The UI opens a reference only after the user clicks it and displays the hostname as parsed by that browser; backend hostname syntax validation does not duplicate every browser URL parsing rule. Users should inspect the displayed host and open only trusted links. The offline docs checker is structural and does not replace the separate human blind retrieval tasks or fixed-viewport screenshot review, which remain pending. The Playwright browser is Nix-provided because the host's bundled Chromium lacks system shared libraries. No AI/provider request or local model execution was run.
