# Student Clock implementation and verification

The Clock tab adds local date/time, a single shared active timer, Pomodoro work/break timing, countdown, stopwatch/laps, and one-off or weekday reminders. Study Plan focused practice uses the same active timer document; starting a second timer is blocked while another is active. Timer display derives from saved epoch deadlines/start timestamps, not accumulated UI intervals. On focus, visibility return, and periodic wake checks, missed deadlines are reconciled once. A suspended Pomodoro skips elapsed phases arithmetically, resumes at one future deadline, and saturates the persisted cycle counter at the schema limit; overdue items stay visible.

Clock state is validated as `clock.json` and stored by `GET/PATCH /clock` through the existing atomic, locked storage service. The old `hamartia.active-practice-session` localStorage draft is converted to the shared clock schema and removed only after the backend confirms its PATCH. A failed save leaves the old localStorage draft intact and can be retried. Backups include clock state while remaining version 1; old version 1 archives without `clock.json` receive empty defaults. Export freezes running timers at the snapshot instant. Restore keeps frozen elapsed/remaining duration, pauses active timers, and disables all imported alarms.

Reminders use the device's local time zone. For recurring wall times, a nonexistent daylight-saving time is normalized forward by JavaScript's local `Date` constructor. An ambiguous fall-back wall time selects the first occurrence. Once it passes, the next recurrence is the following matching weekday, not the second copy of the same wall time. If multiple alarm occurrences were missed while the app was suspended, each enabled alarm emits at most one overdue event and advances directly to its next future occurrence. No notification bursts are replayed.

The app uses the renderer Web Notifications API after an explicit user action and stores an opt-in preference. It checks timer/alarm events only while the app is running and the device is awake. It cannot wake the device or deliver after the app closes; operating-system settings may suppress alerts. Overdue state remains visible in the Clock tab. The exact notification appearance/delivery in packaged Windows and Linux desktop environments remains a manual check.

## Verification

All checks below are non-AI. No model, configured endpoint, local provider route, or real ChatGPT account was called. The browser smoke asserts that `/study-agent/local` is not requested.

- `node --test src/clock/engine.test.js`: 8 deterministic engine checks passed, including pause/resume, countdown expiry, Pomodoro boundaries and large jumps, unique missed-alarm transition, local weekday recurrence, and display formatting.
- `PYTHONPATH=backend /home/necoti/hamartia/.venv/bin/python -m unittest backend.tests.test_backup backend.tests.test_clock_api -v`: 28 checks passed. This includes malformed PATCH non-overwrite, duplicate alarm IDs, one-off timestamp consistency, legacy backup defaults, exported timer freeze, and restore pause/disable behavior.
- `npm test`: 26 frontend tests passed.
- `npm run build`: passed; Vite reports a 792.46 kB minified main chunk (223.21 kB gzip), above its 500 kB advisory threshold.
- `nix shell nixpkgs#chromium --command sh -c 'PLAYWRIGHT_CHROMIUM_EXECUTABLE=$(command -v chromium) HAMARTIA_PYTHON=/home/necoti/hamartia/.venv/bin/python npm run test:browser'`: passed against temporary real FastAPI and Vite servers. It covers failed-then-successful legacy migration, shared practice timer reload, countdown pause/reload, one-off reminder persistence, responsive layout, and existing Study Agent mocked flows; no local-provider endpoint request.
- `nix shell nixpkgs#chromium --command sh -c 'PLAYWRIGHT_CHROMIUM_EXECUTABLE=$(command -v chromium) npm run test:docs'`: passed English default, Turkish navigation, language tags, mobile layout, and no external requests.
- `npm run bench:clock`: passed 96 seeded complete-state comparisons against a separate iterative oracle, explicit 1/2/multiple-phase boundaries, 128 missed alarms, `America/New_York` DST gap/fold expectations, repeated-reconciliation idempotency, and 1e12 ms boundedness. Four explicit plausible-bug controls were all detected (single-phase-only catch-up, UTC wall-time conversion, repeated missed-alarm emission, interval-tick countdown drift). This finite 4/4 targeted sensitivity is not general mutation coverage.
- `PYTHONPATH=backend /home/necoti/hamartia/.venv/bin/python backend/benchmarks/benchmark_clock_api.py`: passed full exact-state round-trip for 128 unique alarms, duplicate-ID invalid PATCH non-mutation (422 and byte-identical saved file), and backup/restore timer/disabled-alarm assertions.
- Combined machine output is preserved in [clock benchmark results](2026-11-15-clock-benchmark-results.json). Engine and API timings are reported separately in the raw output file. On this Linux x86_64 host, the engine batch (96 scenarios) used 11 measured samples, no warm-up; p50/p95 was 0.0855/0.4143 ms. The 128-alarm engine batch p50/p95 was 0.0243/0.0806 ms (11 samples, no warm-up). The API used one warm-up plus 21 measured samples: GET p50/p95 was 0.004220/0.006014 s and PATCH 0.011867/0.013759 s. Both report p50 as median and p95 by nearest rank ceil(0.95*n), without interpolation. A single 1e12 ms reconciliation observation was 0.0017 ms; this is one observation, not a percentile. Timings are local microbenchmarks, not cross-machine guarantees.

The benchmark's API measurements use FastAPI `TestClient`, so they cover route validation and filesystem persistence but exclude loopback socket/network latency and concurrent-client load. The selected DST rules are explicit product policy; regions with other civil-time rules still depend on the host's ICU/time-zone database. Device sleep/wake notification behavior and actual packaged titlebar/OS notification UI are unverified. No Study Agent provider tests or benchmarks were added.
