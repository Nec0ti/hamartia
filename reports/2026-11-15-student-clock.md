# Student Clock implementation and verification

The Clock tab adds local date/time, a single shared active timer, Pomodoro work/break timing, countdown, stopwatch/laps, and one-off or weekday reminders. Study Plan focused practice uses the same active timer document; starting a second timer is blocked while another is active. Timer display derives from saved epoch deadlines/start timestamps, not accumulated UI intervals. The always-mounted ClockProvider reconciles on focus, visibility return, and periodic wake checks, including while another tab is selected. A suspended Pomodoro skips elapsed phases arithmetically, resumes at one future deadline, and saturates the persisted cycle counter at the schema limit; overdue items stay visible.

Clock state is validated as `clock.json` and stored by `GET/PATCH /clock` through the existing atomic, locked storage service. The old `hamartia.active-practice-session` localStorage draft is converted to the shared clock schema and removed only after the backend confirms its PATCH. A failed save leaves the old localStorage draft intact and can be retried. Backups include clock state while remaining version 1; old version 1 archives without `clock.json` receive empty defaults. Export freezes running timers at the snapshot instant. Restore keeps frozen elapsed/remaining duration, pauses active timers, and disables all imported alarms.

Reminders use the device's local time zone. For recurring wall times, a nonexistent daylight-saving time is normalized forward by JavaScript's local `Date` constructor. An ambiguous fall-back wall time selects the first occurrence. Once it passes, the next recurrence is the following matching weekday, not the second copy of the same wall time. The always-mounted ClockProvider reconciles while any app tab is selected. If multiple occurrences were missed while the app was suspended, each due alarm emits at most one overdue event; one-off reminders become visibly overdue, and recurring reminders advance directly to their next future occurrence. This bounds replay per alarm, not the total number of distinct due alarms (up to the schema limit of 128).

The app uses the renderer Web Notifications API after an explicit user action and stores an opt-in preference. It checks timer/alarm events only while the app is running and the device is awake. It cannot wake the device or deliver after the app closes; operating-system settings may suppress alerts. Overdue state remains visible in the Clock tab. The exact notification appearance/delivery in packaged Windows and Linux desktop environments remains a manual check.

- `node --test src/clock/engine.test.js`: 8 deterministic engine checks passed, including pause/resume, countdown expiry, Pomodoro boundaries and large jumps, unique missed-alarm transition, local weekday recurrence, and display formatting.
- `PYTHONPATH=backend /home/necoti/hamartia/.venv/bin/python -m unittest backend.tests.test_backup backend.tests.test_clock_api -v`: 28 checks passed. This includes malformed PATCH non-overwrite, duplicate alarm IDs, one-off timestamp consistency, legacy backup defaults, exported timer freeze, and restore pause/disable behavior.
- `npm test`: 26 frontend tests passed.
- `npm run build`: passed; Vite reports a 792.46 kB minified main chunk (223.21 kB gzip), above its 500 kB advisory threshold.
- `nix shell nixpkgs#chromium --command sh -c 'PLAYWRIGHT_CHROMIUM_EXECUTABLE=$(command -v chromium) HAMARTIA_PYTHON=/home/necoti/hamartia/.venv/bin/python npm run test:browser'`: passed after review hardening against temporary FastAPI and Vite servers. It injects a successful focused-practice POST followed by a failed clock clear, retries and verifies the same record ID, confirms a due alarm persists while Study Plan is selected, and injects a Clock GET 503 to prove controls stay disabled and no Clock PATCH occurs until retry. The smoke also asserts no `/study-agent/local` request and reports `ai_included:false`.
- `nix shell nixpkgs#chromium --command sh -c 'PLAYWRIGHT_CHROMIUM_EXECUTABLE=$(command -v chromium) npm run test:docs'`: passed English default, Turkish navigation, language tags, mobile layout, and no external requests.

Device sleep/wake notification behavior and actual packaged titlebar/OS notification UI are unverified. No Study Agent provider tests or benchmarks were added.
